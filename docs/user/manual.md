# User Manual

This manual is for people using AI Scan as the msutools desktop client. It separates what works today from what is visible in the product but still waiting for live account/API verification.

Current feature status is maintained in one place: [Feature Status](../status.md).

## Who Should Use This Page

- Ordinary users who want to know whether their AI API can be used.
- Users who need to check account, API Key, balance, recharge, and local environment.
- Support staff who need a clear first-pass workflow before asking for logs.

## 3 分钟首次使用

适合第一次打开 AI Scan 的用户。先不要改系统设置，也不要安装东西。

1. 打开 AI Scan。
2. 在首页点击体检按钮。
3. 如果页面要求填写 API 地址，填你的 API 服务地址；不确定就先用默认值或问客服。
4. 如果你有 API Key，粘贴进去再体检；没有 Key 也可以先检查网络连通。
5. 像看系统扫描一样观察进度条和下面的逐项结果：DNS、TCP、TLS、HTTP、模型接口会依次显示检查中、通过、需关注、未通过或已跳过。
6. 如果显示可以使用，先去你的 AI 客户端里试一次。
7. 如果显示需要处理，按页面给出的下一步做；看不懂就把脱敏后的结果发给客服。

当前版本重点是本机体检和 API 连通性。账号登录、余额、充值入口和 Key 管理已经接入真实命令，但仍需要用真实测试账号覆盖更多 live 场景。页面如果显示错误或待接入，不代表你的账号一定有问题。

## First Run

1. Open AI Scan.
2. Start at **Home Health Check**.
3. Enter or confirm the API base URL and API Key when the UI exposes those fields.
4. Run the health check.
5. Read the result by category: account, API service, and local environment.

Current limitation: the desktop UI shell, quick-scan command with API address/Key input, login UI, 2FA challenge flow, account refresh, API Key list/create/delete UI, and professional diagnostic-report preview exist. These paths still need full live test-account verification before the docs can mark every account, balance, recharge, and Key-management case as complete.

## Main Pages

### Home Health Check

Status: Implemented for API connectivity checks; account and Key workflows are partially available and still need live test coverage.

The health check is meant to answer:

- Can the target API domain resolve through DNS?
- Can this computer open a TCP connection to the service?
- Does HTTPS/TLS handshake work?
- Does the HTTP endpoint respond?
- If an API Key is provided, does `GET /v1/models` respond successfully?

If no API base URL is configured, AI Scan should report that the target is missing instead of guessing a service.

The home page now exposes two important inputs:

- API address: use the msutools OpenAI-compatible service root. If you type a URL ending in `/v1`, the scanner normalizes it.
- API Key: optional. Without a Key, DNS/TCP/TLS/HTTP can still be checked; `/v1/models` is skipped.

扫描开始后，首页会显示实时进度，而不是等待结束后一次性出结果。每个检测项都会有当前状态、简短解释和耗时；如果某一项未通过，先处理最靠前的失败项，因为后面的结果可能只是前面失败造成的连锁现象。

### My Account

Status: Partially available; live verification needed.

This page is reserved for:

- Login status.
- Masked account identity.
- Balance.
- Quota or package information.
- Recharge entry.

Current behavior: the page supports email/password login, two-factor verification when the server requires it, logout, account refresh, masked account identity, balance/quota text from `/auth/me`, and a recharge link from public settings. It must not display fake balances or fake user names. Turnstile desktop challenge support is not complete; if the server requires a challenge, use web login or contact support.

### API Key

Status: Partially available; live verification needed.

This page is reserved for:

- Listing existing API Keys.
- Showing masked Key values.
- Creating and deleting Keys.
- Showing the full newly created Key once when the backend returns it.
- Enabling, disabling, editing, grouping, and copying Keys are still planned or pending.
- Showing last-used time when the backend provides it.

Current behavior: the UI lists, creates, and deletes Keys through msutools endpoints when a session is stored. Newly created full Keys are shown only once if the backend returns the plaintext value. Live endpoint compatibility, editing, disabling, copying, grouping, and detailed quota/limit fields still need more verification before ordinary users should rely on the full management workflow.

### Professional Mode

Status: Partially available.

Professional mode shows structured evidence for:

- Recent quick scan.
- Account status.
- System information.
- API Key list.
- Diagnostic report preview.

The report is generated by Rust and marks sensitive values as redacted. It is still a preview; file export and support-ticket upload are not complete.

### Environment Health Check

Status: Partially implemented.

AI Scan can collect:

- OS name and version.
- CPU architecture.
- Shell.
- PATH entries.
- Selected environment variables, with sensitive values redacted.
- Versions for node, npm, git, curl, and docker when available.

Planned checks include:

- System proxy detection.
- DNS resolver details.
- Certificate store health.
- WebView2/runtime checks.
- Client-specific configuration file discovery.

### Client Configuration

Status: Planned.

The product goal is to help configure common AI tools such as Cursor, VS Code, Cline, Continue, Cherry Studio, Open WebUI, Codex CLI, and Claude Code CLI.

The safe rule is read-only first. Before AI Scan writes any client configuration, the implementation must show:

- Which file will be changed.
- The exact before/after diff.
- Where the backup will be stored.
- How to revert.

### Repair Center

Status: Planned.

The repair center should eventually classify fixes as:

- Automatically repairable.
- Requires confirmation.
- Manual only.
- Needs support.

Current behavior: repair UI is a placeholder. No one-click repair command should be advertised as available until the backend returns repair plans and the UI confirms writes.

### Environment Installation

Status: Planned.

The page lists common dependencies such as Node.js LTS, Git, Python, Docker Desktop, WebView2, and VC++ Runtime, but installer commands are not implemented yet.

## Recommended User Workflow

1. Run the home health check.
2. If DNS/TCP/TLS/HTTP fails, fix network, proxy, certificate, or domain issues first.
3. If `/v1/models` fails with 401 or 403, check the API Key.
4. If local tools are missing, install or repair the missing runtime outside AI Scan until installer support is implemented.
5. If account, balance, recharge, or Key list is missing, check whether you are logged in and then check the release note. The current UI has real commands, but some live account/payment/Key edge cases are still being verified.

## 看不懂结果怎么办

先看颜色和第一句话，不要先看日志。

| 你看到的情况 | 先做什么 |
| --- | --- |
| 域名、DNS、TCP、TLS 或 HTTP 失败 | 先检查网络、代理、公司/学校网络限制，或换一个网络再试。 |
| `/v1/models` 显示 401 或 403 | 多半和 API Key、权限或登录状态有关，重新复制 Key，确认没有多余空格。 |
| 显示 429、余额、额度或套餐相关提示 | 先去官网确认余额、套餐或用量。当前桌面端余额/充值入口来自真实接口，但还需要更多 live 场景验证。 |
| 账号、余额、充值、Key 管理显示错误或待接入 | 先确认是否已登录；不要反复重装。查看更新记录或联系支持。 |
| 本机缺少 Node、Git、Docker 等工具 | 当前版本主要负责发现问题，自动安装仍未承诺可用；按页面提示去官方入口安装。 |
| 结果里有很多英文或代码 | 不需要逐行理解，把脱敏报告或截图发给客服。 |

不要做这些事：

- 不要把完整 API Key 发到聊天软件。
- 不要把 Cookie、Token、Authorization、refresh token 发给别人。
- 不要看到失败就立刻重装系统或删除客户端配置。
- 不要把“官网能打开”当作 API 一定能用；API 还需要单独检测。

## 给客服发什么 / 不要发什么

可以发：

- AI Scan 首页结论截图。
- 失败项名称，比如 DNS、TLS、HTTP、`/v1/models`。
- API 地址，但不要带 Key。
- HTTP 状态码，比如 401、403、429、500。
- 脱敏后的诊断报告。
- 你使用的客户端名称，比如 Cursor、Cline、Cherry Studio、Open WebUI。
- 你大概什么时候开始不能用。

不要发：

- 完整 API Key。
- 账号密码。
- 验证码。
- Cookie、Token、Authorization、refresh token。
- 代理密码。
- 未脱敏的日志或原始请求。

如果客服要求更多信息，先确认是否可以脱敏。看见 `sk-`、`Bearer`、`Cookie`、`token`、`password` 这类字样时，默认不要直接发原文。

## Privacy Notes

AI Scan should redact sensitive values in diagnostics. Do not share unmasked API Keys, tokens, cookies, or proxy passwords in screenshots or support tickets.
